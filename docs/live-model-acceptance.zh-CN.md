# v0.5.10 真实模型验收

[文档索引](README.zh-CN.md) · [English](live-model-acceptance.md)

2026-11-05（Australia/Sydney），使用用户配置的 `gpt-6-astra`、Chat Completions 接口完成 **12 轮、34 次已记录 API 调用**。服务商返回的模型名同为 `gpt-6-astra`，业务账号和扣款均为本地合成数据。[逐轮证据](../evals/releases/v0.5.10/live-model.json)。

## 发现与修复

| 问题 | 修复 | 验证 |
|---|---|---|
| “刚才的403”等中文紧连错误码漏检，简短追问遗漏套餐规则。 | 按完整编号匹配，403 和余额兜底查询补齐套餐规则依赖。 | 换题再切回命中 ERR-401＋PLAN-001；1401 / 1403 不误当成 401 / 403。 |
| 正确的 `-$7` 余额和“补足 $7 欠款”被金额质检误拦，导致重试和回退。 | 保留货币前负号；仅由本次查询到的负余额支持对应欠款金额。 | 原问题复测从 5 次调用降为 3 次，使用真实模型回复；虚构正余额、退款、旧欠款及币种错配仍被拦截。 |
| 管理员依据只写 local，容易把财务固定模板误认为模型失败。 | 分别说明真实模型、财务模板和实际回退，并标注模型分诊是否成功。 | 合规回正明确显示模型分诊成功、采用财务模板、没有回退。 |

## 已验收流程

- 错误＋套餐、退款＋额度组合检索；暂停的话题不继续混入答复。
- 管理员依据对应实际知识与查询；客服、客户接口不返回该内容，管理员个人视图也无工作台权限。
- 合规小额和首次 $6 欠款各写账一次；7 天内再次出现 $7 欠款不能自动回正。客服 `/recharge` 可覆盖资格条件，结果仅内部显示。
- 人工回复后实际等待 60 秒才生成内部建议，复用已确认的客户端、模型和配置步骤；客服发送后客户才看到。
- 恢复 AI 后读取最新兜底设置、请求 #37 的 $0.12 扣款及 $18.38 余额，不沿用旧 $18.50。发送与撤回自动同步，无需手动刷新。

调查中出现过一次金额误判回退、两次知识遗漏，修复前后记录分别留存，不能将全部原始轮次说成首次通过。普通答复使用分诊、生成、质检三阶段；合规财务写入在分诊后使用固定模板。管理员摘要与答复同次生成。

## 复现与边界

在独立副本执行 `python3 scripts/start_demo.py --provider openai`，按提示输入地址、隐藏 Key、模型和协议，再用[演示账号](../README.zh-CN.md#演示账号)测试。[报告](../evals/releases/v0.5.10/live-model.json)保存原始合成问题、依据与输出；$6 / $7 场景使用独立账本测试数据，不是真实消费。

未提供服务商单价，因此仅统计 Token，不估算金额。5 次降为 3 次只适用于已修复的用例，不代表整体节省比例；总调用不含启动检测。本次不证明生产解决率、未见题准确率或其他模型兼容性。
