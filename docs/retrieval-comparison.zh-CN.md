# BM25、字符 n-gram 与组合检索对照

[文档索引](README.zh-CN.md) · [English](retrieval-comparison.md)

实验版本 **v0.5.6**，日期 2026-11-04，使用 v0.5.5 冻结数据。本版保留原始报告。

**主要瓶颈是覆盖度过滤：正确知识已进入候选，却在生成前被移除。** 三种方法在本集的最终排序完全相同，不能据此声称组合检索优于 BM25。

## 结果

| 分区 | 方法 | 最终 Recall@4 | 最终 MRR@4 | 原始 Recall@4 | 原始 MRR@4 |
|---|---|---:|---:|---:|---:|
| 开发集 | BM25 | 67.65% | 70.59% | 100.00% | 92.65% |
| 开发集 | 字符 n-gram | 67.65% | 70.59% | 88.24% | 79.41% |
| 开发集 | 组合 | 67.65% | 70.59% | 100.00% | 92.65% |
| 保留集 | BM25 | 68.75% | 75.00% | 100.00% | 91.67% |
| 保留集 | 字符 n-gram | 68.75% | 75.00% | 87.50% | 79.17% |
| 保留集 | 组合 | 68.75% | 75.00% | 100.00% | 91.67% |

最终依据完整题数为开发集 **11/17**、保留集 **5/8**；无答案误召回为 **0/2**、**0/1**，这些题过滤前均有非空候选。检索异常为 0。

Recall 按题平均必要知识命中比例，不是“正确题数 / 总题数”。按实际返回数计算的平均精确率为 **59.80%**、**62.50%**，分别有 4 道、2 道知识可答题夹带无关依据。本实验没有生成客户回复。

## 共用设置

| 项目 | 固定配置 |
|---|---|
| 语料 | 每题均使用完整 10 条知识 |
| 查询 | 完整问题，不拼接标签、正确 ID 或改写文本 |
| BM25 | `k1=1.5`、`b=0.75`，按单次查询最大分数归一化 |
| 字符得分 | 二元 / 三元字符计数余弦相似度，无 Embedding |
| 权重 | BM25 `(1,0)`；字符 `(0,1)`；组合 `(0.62,0.38)` |
| 业务规则 | 相同来源加权、优先级规则，同分按语料顺序 |
| 候选与过滤 | 先取 4 条，再要求覆盖度 ≥ 0.12，不回填 |

这是现有客服检索流程内的消融对照，不是纯算法通用排名。为记录得分分量，三种方式都会计算两类基础分数，不能用执行时间推断部署后的速度或费用优势。

## 开发集定位与选择

BM25 / 组合检索有 6 个必要依据进入开发集 Top-4 后被过滤，涉及套餐与钱包的口语表达、小额回正、退款、失败扣费，以及只召回一个子问题的退款 / 额度组合题。

字符检索另有 2 个必要依据未进入有效候选。字符相似不能自动理解业务同义词；直接取消覆盖度阈值又会放入本次无答案题的候选，因此本轮没有修改阈值或知识。

预先设定的选择顺序为：无检索异常、Recall 更高、无答案误召回更低、MRR 更高，并列保留原组合方案。**没有执行参数搜索。** [开发集逐题分析](../evals/retrieval/experiments/v0.5.6/development-cases.zh-CN.md)。

## 复跑顺序

```bash
python3 scripts/evaluate_retrieval.py development
python3 scripts/evaluate_retrieval.py freeze --development-report runtime/retrieval/development.json --rationale "复现发布配置；开发集并列，沿用组合检索，不调参"
python3 scripts/evaluate_retrieval.py holdout --freeze runtime/retrieval/frozen.json
```

先检查开发集再冻结。命令拒绝覆盖已有报告；重跑需指定新的 `--output`，后续步骤引用对应路径。保留集运行必须满足数据、代码和参数哈希一致。

本实验外部模型调用为 **0**，没有测量回答质量、客户等待时长、重试减少或每单费用。改善证据覆盖能否带来业务收益，仍需回到完整工单流程验证。
