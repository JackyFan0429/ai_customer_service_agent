## 4. 后续检索指标定义

以当前网站知识查询为主要评测对象。每题记录固定知识快照、查询文本、相关且当时有效的知识 ID 集合 `Gq`、题型和复核状态。需要查询余额等动态账户信息的任务，不能仅因静态知识不包含账户值就标为“知识库无答案”。多轮业务理解和独立检索分别统计。

设 `Rq` 为经过现有发布/时效及覆盖度规则后、实际可供生成使用的有序结果（最多 4 条）。后续报告同时保留原始候选，便于区分排序失败和过滤失败。

| 指标 | 分母与计算方式 | 边界 |
|---|---|---|
| Recall@4 | 对 `Gq` 非空的题，计算 `|Rq ∩ Gq| / |Gq|`，再对题目取平均 | 检索异常或空结果计 0；不把无答案题放入分母 |
| MRR@4 | 对上述有答案题，首个正确知识的排名为 r，得分 1/r；前 4 条没有则为 0，再取平均 | 只衡量第一个正确结果的位置，不代表所有必要规则都齐全 |
| 无答案误召回率 | `Gq` 为空且最终返回非空结果的题数 / `Gq` 为空的全部题数 | 异常留在分母并单列，因此 `1 − 误召回率` 不能当作成功拒答率；不是模型误答率 |
| 检索异常率 | 检索异常的题数 / 全部检索题数 | 异常不从总题数中删除 |

开发集与保留集按相似问题组划分，同一问题的改写放在同一侧。保留集不参与调参。比较 BM25、n-gram、组合检索时，语料、知识有效期、查询、Top-K 和过滤条件一致；首次对照沿用现有配置。分母为 0 的指标写 `null`，不写 0% 或 100%。总体结果之外保留题型结果及失败样本。

## 5. 回答质量与业务指标定义

现有 29 场景只检查最后一轮运行的路由、所需工具、必要事实片段和可选的禁止内容/动作条件，不能称为逐轮语义正确率。旧版 63 轮逐轮检查，但文本匹配和证据 ID 合规仍不能证明每个论断真实。

后续端到端验收应记录：是否回答当前问题、业务事实是否与最新查询一致、是否重复索要已提供的信息、操作与人工权限是否符合预期、是否有无依据的承诺。标签与判定依据需要复核，不能只让生成模型给自己打分。

| 指标 | 口径 |
|---|---|
| 场景通过率 | 满足该场景预先列明的全部必要条件 / 全部场景；失败与异常保留在分母 |
| API 调用成功率 | 获得并通过协议/结构验证的调用尝试 / 全部调用尝试；和内容复核通过率分开 |
| 模型回退率 | 本应走模型路径且发生 `model_fallback` 的运行 / 本应走模型路径的运行；local 模式和明确使用固定业务模板的操作分别报告 |
| 重复提问、无依据回答、错误操作 | 按人工复核的具体标准记录问题与证据，当前无独立统计值 |
| 自动解决率、满意度、重开率 | 上线指标，需先约定解决与重开观察窗口；当前没有真实用户样本，暂不报告比例 |

资金操作按规则需要人工批准，是正确的业务路由。不能把“没有转人工”单独当成成功，也不能把来源标为真实模型当作回答正确。

## 6. 时间与成本口径

| 现有记录 | 覆盖范围 | 不覆盖的内容 |
|---|---|---|
| `quality.model.calls[].elapsed_ms` | 每次分诊、生成、复核尝试的请求及结果处理耗时 | 浏览器收到消息时间、等待人工时间 |
| `runs.elapsed_ms` | 本轮工作流生成阶段，包含业务查询、模型和检查 | 队列等待、发布和浏览器同步耗时 |
| 离线评测 `duration_ms` / `elapsed_ms` | 当前机器的本地评测执行耗时 | 真实模型延迟和客户实际等待时间 |
| `quality.model.calls[].usage` | 服务商返回时保留输入、输出及总 Token 字段 | 未返回的用量、服务商最终结算金额 |

第 4 阶段统一 `prompt_tokens`/`input_tokens` 和 `completion_tokens`/`output_tokens` 的含义，不重复累加同义字段。每次尝试分别统计，包括重试与内容修订。正常模型答复通常调用分诊、生成、复核三次；固定业务模板等路径单列。部分失败调用可能没有用量，不据此假定免费。

估算费用以明确配置的服务商、模型、币种、单价和适用日期为依据。输入与输出分别计费后求和；缓存等特殊计价只有字段和价格依据齐全时才计算。缺失用量或单价标为未知/不完整，不补零。没有提供计价依据时，先报告 Token 和调用次数。

模拟账户的余额、请求日志 `cost_units` 是被客服查询的演示业务数据，不能当作客服模型的 API 费用。模型费用也不等于每单总成本；人工处理成本需额外统计处理分钟数与成本口径。

本阶段仅盘点可用字段和历史记录完整性，不新增费用估算，也不改变模型调用次数。单次本地耗时只描述本次运行，不据此宣称速度提升或线上 P95；后续性能比较需同环境、同场景并重复采样。

## 7. 复跑方法

在项目根目录、Python 3.11+ 环境运行。以下命令只使用合成资料和隔离临时数据库；不需要 API Key。完整测试涉及 PDF 导入，需环境已有 `pdfplumber`（项目可选 `[pdf]` 依赖）。本次两套评测使用 Python 3.13.15；完整测试使用 Python 3.12.14、pdfplumber 0.11.9，均在 macOS arm64 上运行。

```bash
python3 scripts/evaluate_desk.py --as-of '2026-11-04T00:00:00+11:00' --output runtime/stage1-desk-recheck.json
python3 scripts/evaluate_agent.py --provider local --label stage1-recheck --cases evals/baselines/lumen-v0.5.3-2026-11-04/inputs/legacy-scenarios.jsonl --corpus evals/baselines/lumen-v0.5.3-2026-11-04/inputs/legacy-corpus.jsonl --output runtime/stage1-rag-recheck.json
python3 -m unittest discover -s tests -q
```

网站评测从项目的 `desk/data` 及种子代码读取数据；比较前对照清单中的哈希确认一致。若修改知识、题目或评分器，记录为新实验版本，不能把它与本基线直接当成同条件改进。默认不带 `--as-of` 时仍使用当前时间；该参数仅作用于离线命令，不修改网站时钟或现有工单。
