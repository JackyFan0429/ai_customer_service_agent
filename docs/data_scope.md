# Data scope and anonymization

**English** | [简体中文](data_scope.zh-CN.md)

AI Customer Support Agent & Knowledge Base Governance is a personal prototype for an AI API support setting. It has not been connected to real support operations and does not represent an official company product. Follow the [main tutorial](../README.md) to reproduce the public demo.

## What is included

| Path | Contents |
| --- | --- |
| `support_agent/demo/corpus.jsonl` | 19 synthetic records with fictional client/model labels and `.example` addresses. P1/P2 simulate source precedence; far-future dates are demo fixtures. |
| `evals/scenarios.jsonl` | 48 development scenarios and 63 messages, version `synthetic-v2-neutral`; AI-authored labels await owner review. |
| `evals/results/` | Executed before/after reports with input, grader and implementation hashes. |
| `evals/baselines/pre_iteration.patch` | A patch that reconstructs the earlier logic using neutral names. It does not include the original branded sources. |

## What is not included

Original customer cases, internal knowledge, public-site excerpts, source-review logs, private derived datasets, and old demonstration databases are separately archived by the project owner. Real sources and audit records are preserved privately; fictional URLs have not been substituted into historical evidence.

The project description's 1,659 historical cases, 660 archived or review-required cases, and 1,086 retrieval records describe an earlier private snapshot. They are not record counts in this repository, nor statistics regenerated by the current neutral classification rules. The public package directly reproduces the 19-record demo and 48 development scenarios.

## Adding your own data

The product and client rules are editable neutral examples. Map channel-specific message identifiers to `message_id`. Before using real data, configure classification, redact content, verify sources and expiry, and conduct a separate evaluation. The [operations guide](operations.md) explains the import workflow.

Only provider values, environment variables and default endpoints needed for model API integration retain technical vendor identifiers. Default `local` mode makes no model requests; project branding, demo responses and example knowledge use neutral labels.
