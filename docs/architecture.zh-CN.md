# 系统架构

[English](architecture.md) | **简体中文**

个人原型，由程序编排的 RAG 客服工作流。没有实时业务工具或自主规划执行循环。

```text
离线：历史工单 → 规则分类与质量分层 → 官方资料核对 → 冲突标记 → 检索语料

在线：用户消息 + 最近 8 条会话消息
  → local 规则理解 / 模型结构化语义理解
  → 独立查询（新问题替换旧问题，新错误码替换旧错误码）
  → BM25 + 字符 n-gram 检索
  → 错误标识、相关度、时效、冲突、受众过滤
  → 对公开材料应用正文预算
  → answer：独立查询及预算内证据传入生成，返回材料引用
    clarify：补充信息；未解决追问保留当前主题
    escalate：提示人工核验，不执行工单操作
  → Web 保存 SQLite；CLI 仅进程内存
```

| 模块 | 职责 |
| --- | --- |
| session.py | 有界消息历史；从用户消息重建本地主题，不从助手回答抽取错误码 |
| providers.py | 本地摘录和规则理解；Responses API 的结构化理解与生成 |
| retrieval.py | BM25 + 字符二元／三元组余弦相似度；完整标识匹配 |
| policy.py | P1/P2 时效、冲突、受众过滤；账户／实时状态升级 |
| prompts.py | 不可信材料以数据传入；共享证据正文预算 |
| agent.py | 编排、查询标识保护、生成上下文与引用对齐 |
| database.py / web.py | SQLite 消息持久化、HTTP 接口与页面 |
| scripts/evaluate_agent.py | 固定日期、逐轮验收和场景级对比 |
| scripts/review_knowledge.py | 到期盘点和待核验清单 |

P0 实时工具尚未接入。P1 官方知识在复核期限内可支持相应事实；P2 历史案例仅作排障线索；P3 低质量或未解决材料不进入主检索。包内演示资料为虚构的 P1/P2 角色，不是官网政策。

restricted_internal 不应进入生产检索语料，运行时亦拒绝用于回答；agent_internal 正文不传给模型或客户，当前只保留候选 ID，未实现复杂内部业务决策。

本地规则对短错误码更新及未解决追问提供有限支持。长对话超过消息窗口后可能丢失主题；复杂省略和否定更正仍需扩展评测。模型理解需要独立真实模型评测。排序权重和 Top-K 尚未通过业务流量调优。

引用标识生成时可见材料，local 摘录只引用实际选中的首条资料；这不保证每个生成论断都被支持。预算计算证据正文字符，不是 Token 预算。
