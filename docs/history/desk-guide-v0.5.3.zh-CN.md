## 业务流程

客户提交工单 → 立即保存并返回页面 → 后台任务分诊、查询、生成、质检 → 通过条件后直接发送 → SSE 通知双方更新。无法自动处理的业务、业务查询缺失、最终回复质检异常、余额审批等待人工。

模型分诊、生成或复核失败，以及模型草稿未通过检查时，回退到本地基准答复并重新质检。`quality.warnings` 记录降级说明，`quality.blocking_warnings` 记录缺失业务证据，`quality.model_fallback` 标记实际降级。仅模型降级不会阻止通过质检的本地回复自动发送；人工保护、全局开关和操作审批仍独立校验。客服侧显示来源与原因，事件时间线记录降级和自动发送；客户只看到最终公开回复。

人工回复或接管后，客户的新消息启动 60 秒等待任务。期间人工回复、关闭工单或新的客户消息会取消旧任务。到期生成的只是内部建议，不会自动发给客户。人工发送建议也视为人工介入，延续 15 分钟保护。手动“重新生成”始终需要人工发送。

明确接管使用 `mode=human`，不因 15 分钟结束而恢复。普通人工回复使用 `human_until`，窗口结束后下一条客户消息可以自动回复。点击“恢复 AI”清除保护并取消旧待处理任务，下一条消息按当前全局开关处理。

管理员关闭全局 AI 开关会取消尚未完成的自动发送任务，并在发送前再次校验权限。重新开启不会追溯发送旧草稿。人工优先的延迟建议不受直接发送开关影响。

头像切换改变当前登录会话的 `view_mode`，不改变账号角色。切到个人空间后，服务端同样拒绝客服/管理接口，创建工单固定归属本人。另一独立会话不受影响；普通浏览器标签页共享 Cookie，因此测试多账号要使用独立浏览器会话。

登录使用 PBKDF2 密码散列、会话 Token 散列、HttpOnly/SameSite Cookie；写操作检查 CSRF 与 Origin。停用、重置密码及退出使相应会话失效。实时通道也检查会话有效性，只发送版本号，不发送其他客户内容；具体页面仍通过授权 API 查询。

## 实时、并发与撤回

`Database` 在成功提交写事务后通知版本变化，回滚不会通知。`/api/events` 是经过登录验证的 SSE 通道。浏览器收到通知会读取当前页面数据；断线每 5 秒补同步，恢复时读取最新状态。定期刷新也更新过期的人工保护提示。

前端保留正在输入的文字、同一份草稿的修改、展开的查询记录和滚动位置。新一版草稿使用新 ID，不会套用旧草稿的编辑文本。编辑弹窗暂缓重绘，关闭后补同步。

`generation_jobs` 持久化任务与到期时间。网络调用在数据库锁外执行，慢模型不会阻塞客户读页面或人工回复。结果写入前校验任务是否被取消、客户消息是否仍为最新、工单是否解决；自动发送前再验全局开关和人工保护。重启会重新排队未完成的任务，重新检查有效性。

撤回保留消息 ID，写入 `retracted_at/retracted_by`，客户消息与列表摘要统一替换为“已撤回”。AI 原文仅保留在本地内部审计记录中。此操作不撤销已执行的账本或退款状态。

## 账号、套餐与数据库

数据库包含用户/会话、套餐、订单、发票、请求、Key 元数据、账本、平台状态、工单、消息、生成任务、运行记录、事件、设置、知识和评测报告。

管理员可以新增、修改套餐名称、额度、已用量、刷新时间、到期时间和状态。一个账号最多保留一个由管理界面激活的生效套餐，旧套餐停用但不删除；当前套餐优先返回到客户页面与工具查询。成功模拟请求消耗符合有效期及额度条件的套餐；失败请求不扣费。

余额使用整数单位存储（10,000 单位 = 1 USD）。调整余额记录变动前后差额。回正建议在发送时再次核验来源和金额，并将账本、余额和公开回复放在同一事务里。

旧版数据库启动时自动迁移角色约束、会话视图、撤回字段和后台任务表，保留原有记录。首次迁移应用自动发送、15 分钟保护和 60 秒等待；之后保留管理员保存的配置。建议先停止旧程序、保留数据库备份，再使用新程序打开同一数据库。

## 模型诊断与对话上下文

v0.5.3 记录同一工单的首个主题及最近的主题切换（最多 8 组）。明确暂停的主题不会参与本轮业务查询或操作；“回到最开始那个问题”可从先前客户消息恢复对应主题，并重新查询当前套餐、余额或订单。多个旧问题指代不明时先澄清。仅确认其中一个问题恢复时，不直接关闭整个多问题工单；明确确认全部完成后才关闭。旧工单可从已有公开客户消息补建主题记录。

套餐查询会读取 Key 的余额兜底开关，解释按该 Key 使用时的实际规则；时间字段附 UTC、北京时间和悉尼时间的明确换算（系统有对应时区数据时），不会将日期分隔符当作负号。负余额仍须核验账本来源、金额及冷却期；用户暂停回正后切换到模型配置，不会再次创建回正或退款操作。

v0.5.2 将数字校验分为两类：时间、错误码和请求编号可来自本轮问题、公开历史或查询；余额、扣费和退款金额仍需当前业务证据，工具的整数金额先按币种和单位换算。用户希望保留的金额只能在明确归属于用户诉求的句子中引用，不能变成已确认余额或获批退款金额，也不自行推算退款金额。生成和发布使用同一组证据校验，避免生成通过、发送时再次误拦。

连续追问保留未完成的业务主题，简短致谢不会清除退款上下文。“到哪一步了”“客服登记的那笔”等追问重新查询当前订单；“用不了这么多余额”不作为技术故障。退款政策/手续费咨询不自动登记退款，缺少费率时明确需要核验。排障的本地备用回复也读取客户已提供的时间、完整报错及没有请求编号的说明，避免再次索要相同信息。明确确认“已经可以正常用了”可标记解决；“应该可以正常用了”先确认恢复，同时存在未核实事项时不提前关单。

生成与复核同时收到 `approved_facts`、本轮问题和公开对话；基准回复是摘要，不应被复核误当成唯一事实来源。内容质检失败会给模型一次修订机会，再次执行规则校验与模型复核，依然不通过才降级。`quality.revision_attempted`、`quality.model_draft_check` 和 `quality.model.review` 记录修订及拦截原因；每次质检调用的 `content_review` 保留对应结论。反馈有条数与长度限制，并遮盖密钥、接口 URL 和邮箱。

真实模型启动先进行分诊、回复、质检三次真实请求；失败会停止，不静默改为离线成功。`providers.model_ssl_context` 载入默认信任及可用的 certifi 根证书，自定义 CA 设置优先，保持证书和主机名验证。

每次工单生成使用独立的 `DeskModel` 调用记录，避免把其他工单的阶段混在一起。`quality.model` 保存配置模型、服务商返回的模型名、阶段成功/失败、时长、可用的 token 数、上下文条数与回复来源；异常只保存固定错误类别、说明和 HTTP 状态，不保存原始异常、鉴权信息或 API 地址。输出因长度不完整时最多重试一次（4,096 → 8,192 输出 token），已识别的 GPT-5/6 模型请求低推理强度。

上下文从数据库读取本工单当前消息之前、已公开的 customer/assistant/human 消息。最多最近 24 条和约 16,000 字，单条最多 2,500 字；截断有标记，撤回消息仅用占位符。模型分诊、生成、复核都收到相同上下文；当前业务查询优先于历史消息，历史人工回答不会授权新业务写入。生成期间的新客户消息和人工介入仍按原任务取消规则处理。

“现在应该好了”属于确认恢复，先回应并确认；明确“确认，已经可以用了”才完成工单，包含否定、新问题或疑问时不自动关闭。客户可看到每条消息的实际来源，客服可查看阶段记录和人工消息是否进入上下文。

## 模型与扩展入口

本地模式只用标准库，规则引擎仍执行查询、生成、质检、自动发送和人工协作。真实模型通过终端交互临时填写 Base URL、隐藏 Key、模型 ID 和 Responses / Chat Completions 接口。配置不写入文件、数据库或上层 Shell；停止后重新输入，已有进程环境变量可主动复用。

模型只接收本轮问题、有限背景和工具证据，不持有数据库写工具。业务写入由受权限保护的应用代码执行。新增知识在 `AdminConsole` 管理；新工具在 `desk/tools.py` 注册；路由与基准答复在 `desk/engine.py`；行为回归在 `desk/data/evaluation_cases.json`；协作/权限/计时测试在 `tests/test_live_workflow.py`。

核心运行命令、全部测试命令和打包方式见 README。发布 ZIP 排除运行数据库、会话、真实凭据、原始 JSON 和未复核候选数据。此版没有真实支付、邮件发票、附件 OCR、定时续费/额度重置或生产部署。
