# 合成客服场景离线评测

[English](evaluation.md) | **简体中文**

## 目的与限制

验证固定客服场景是否选择合适路由、使用预期证据、覆盖必要回答点并避免明示禁止结论。先定义任务与标准，再固定样本比较迭代。

共 48 个合成开发回归场景、63 轮消息，包含 14 个多轮场景。题目和标签由 AI 编写，待项目本人逐条复核；不是独立人工标注集、盲测或真实流量效果。知识库为 19 条虚构记录。

开发期间可见并使用了这些题目。后续应按真实需求分布增加任务，按工单或相似问题簇划分开发集与独立保留集。

## 样本格式与评分

`evals/scenarios.jsonl` 每行一个任务，包含 id、category、来源、标签状态、知识版本、固定日期，以及 corpus_ids 指定的可用资料快照。不同快照用于模拟缺资料、仅过期资料等情形。

turns 按顺序执行，每轮有问题、预期路由、预期和允许的证据 ID、必要回答点及禁止结论。required_points 外层为 AND，内层同义词列表为 OR。词组检查可能误判否定或复杂表达，不能代替事实核验。

每个任务使用独立会话；任何一轮失败，整个场景失败。异常保留在分母内。日期固定为 2026-09-19；虚构资料的远期日期仅用于演示夹具，不适用于真实政策。

| 指标 | 分子 / 分母 |
| --- | --- |
| scenario_pass | 所有轮次均通过的任务 / 全部任务 |
| turn_pass | 路由、回答点、禁止结论和证据均通过的轮次 / 全部轮次 |
| route_accuracy | 路由与标签一致的轮次 / 全部轮次 |
| answerable_acceptance | 完整通过的可答知识问题 / 标签要求回答且有证据的轮次 |
| evidence_rule_violation | 引用超出允许集合的知识回答 / 实际返回引用的回答 |
| escalation_recall | 正确升级轮次 / 标签要求升级的轮次 |
| multi_turn_success | 完整通过的多轮任务 / 全部多轮任务 |

evidence_rule_violation 仅检查证据 ID，不能称为幻觉率。无依据结论仍可能出现在引用正确的答案中，需要人工或经校准的逐论断评价。报告保留每轮输出、失败检查、实现文件哈希、语料与题目哈希、评分脚本哈希。

elapsed_ms 为本次本地执行耗时，不代表模型延迟。local 不调用模型；API 成本和 Token 未采集时写 null。

## 复现

```bash
python scripts/evaluate_agent.py --output runtime/evaluation.json
python scripts/evaluate_agent.py --output runtime/evaluation.json --fail-on-regression evals/results/after.json
python scripts/reproduce_baseline.py
```

最后一条在临时目录恢复改动前代码并验证哈希，再运行相同场景，结果写入 runtime/reproduced_before.json。基线是 2026-09-19 修改前的本地 40 测试版本，不是此前 GitHub 的 38 测试版本。

匿名化后，使用同一份 `synthetic-v2-neutral` 资料和题目分别重跑改前逻辑与改后逻辑，再重新生成报告与补丁。中性名称可能影响字面检索分数，所以没有直接沿用旧报告或手改哈希；本次两组验收计数与匿名化前一致。

题目、语料、评分器、provider 或固定日期变化时，比较命令拒绝视为同条件实验，需要重新建基线。新增样本不能偷偷移出分母或覆盖旧报告。

## 本次结果

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 完整场景 | 39/48 | 48/48 |
| 完整轮次 | 53/63 | 63/63 |
| 路由 | 56/63 | 63/63 |
| 可答问题验收 | 29/33 | 33/33 |
| 证据集合违规 | 3/32 | 0/33 |
| 升级召回 | 9/9 | 9/9 |
| 多轮任务 | 9/14 | 14/14 |

原先失败的 9 个场景涉及通用退款政策误升级，401/1401、401/E401、E401/E4012 混淆，短错误码变更和未解决追问缺少主题。修复后原先通过的 39 个场景均未回退。

软件测试另验证 Web 恢复会话、会话隔离、生成使用独立查询、改写保留标识、引用预算一致、跨日到期检查等机制。本次没有运行真实模型端到端评测。
